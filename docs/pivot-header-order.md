# 透视表手动切换表头顺序

入口：编辑透视表 → 样式 → 基础样式 → 表头顺序。指标放在列时显示这项设置；指标放在行时隐藏，原行指标布局保持不变。仅提供两个手动选项，不做自动判断。

- 维度优先（默认）：月份 → 业绩；每个月下显示相应指标。
- 指标优先：业绩 → 月份；单指标表的业绩表头横跨月份，多指标表为各指标分别建立月份子表头。多层列维度保留自身顺序，整体移到指标下面。

配置保存在现有 customAttr.basicStyle.pivotHeaderOrder，值为 dimension-first / measure-first。旧图表没有此字段时保留维度优先。S2 的 fields.customValueOrder=0 将指标放到外层；切回维度优先时不设置该参数，由引擎使用原顺序。pivotHeaderLayout.ts 生成字段配置，table-pivot.ts 接入；不修改查询、日期分组、行列轴字段或数据。沿用现有样式变更及保存 JSON 流程，无数据库迁移。总计别名按节点 query 中的指标键解析，兼容指标位于外层时总计叶节点的值为“总计”的情况。

验证：tests/pivotHeaderLayout.test.cjs 使用项目实际安装的 S2 PivotDataSet 及项目 CustomPivotDataset 总计逻辑，比较两种顺序在单/多指标、单/多列维度中的单元格与总计结果、月份排序；验证旧配置、指标放行、JSON 配置往返和总计别名。编辑组件编译、修改文件 ESLint 通过。本轮浏览器无可用连接，尚未进行实际页面显示及保存发布验证。

前端开发服务刷新即可查看；本功能不需要重编译后端。
# 多指标总计（2026-10-14）

指标优先时，S2 原生总计分支会生成一个没有 `$$extra$$` 指标身份的叶子列。前端现在在表头布局完成、数据单元格布局开始前，将该叶子改为“总计”分组，并按指标顺序生成各指标的总计叶子。每列保留指标结果键、格式和现有汇总/占比口径。

调整直接修改原列叶子数组，保持原生 `getCellMeta` 闭包与层级索引一致。随后更新列坐标、父表头跨度；列自适应继续按格式化后的实际总计测宽。此路径不依赖首次构造时尚未赋值的 `sheet.facet`。

回归覆盖真实 S2 表头生成、原生单元格元数据查询、业绩与加权占比两个指标、日期与星期双层表头，以及三种列宽配置。单指标、维度优先和指标行头保留原路径。
