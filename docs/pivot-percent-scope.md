# 透视表占比计算范围

入口：指标下拉菜单 → 快速计算 → 占比 → 设置范围。提供全表、按列、按行，以及当前真实行维度的父分组层级；最后一层分类不作为父分组候选。按“年”分组保留其上级渠道和年份，月度列在各自月份内计算，总计重新按当前筛选期间的原始值计算。字段使用 resultKey，区分同一日期字段的年份与月份 placement。

配置沿用指标 compareCalc JSON，新增 percentScope（table / column / row / rowGroup）及 percentGroup（行父分组 resultKey）。旧配置缺省 table，保持原全表口径；没有自动判断。

后端 PivotPercentCalculator 在完整筛选查询结果中建立分母分组，以 BigDecimal 计算比例；不改变行权限、筛选、日期分组或指标聚合。开启新范围时，使用 resultMode=all 的查询副本，避免前 N 条截断改变分母；返回所有结果供透视表展示。保留 percentBasis 原始聚合值，并将转换后的比例交给既有表格/导出流水线。普通全表占比增加零分母处理，返回空值。

前端 CustomPivotDataset 的总计计算优先使用 percentBasis：按当前总计/小计查询保留的维度计算分子、按占比范围计算分母。月度占比不可直接求和或平均成年占比。分组汇总索引按指标及维度集合缓存，重设数据时清空；支持原有全局排序编码的维度解码。Excel 查询响应也保留 percentBasis，明细 sourceData 则使用已经转换的占比值。

首版新范围仅支持 SUM、COUNT。AVG、去重计数及非可加聚合不启用新范围；前端禁用选择，后端再次校验，避免把组内平均值/去重数相加当作总体。后续支持这些类型需增加分母粒度的原始查询。参与计算的字段有脱敏规则时暂不启用新范围，避免原始基数绕过脱敏输出。零分母返回空值，显示遵循表格空值设置。分组移除、变成末层或身份不匹配时明确报错，请重新选择分组。

验证已完成：编译更新的 SDK Compare DTO、后端计算器和 DefaultChartHandler；Java 测试覆盖多个渠道/年份/月、SUM/COUNT、行/列分母、placement 身份、原始基数不变、过期分组与非可加聚合拒绝、零分母和脱敏保护。前端测试实际调用项目 CustomPivotDataset 与安装的 S2，验证 7月 80%、8月 10% 的品类总计为 33.33% 而非 90% 或 45%，并验证分组总计为 100%、缓存清理、旧配置以及设置组件编译。既有透视表表头和参数回归测试及修改文件 ESLint 通过。

已通过实际 S2 数据查询和 Excel 工作簿导出回归，尚未自动验收真实仪表板页面。修改涉及前端、SDK 和后端，部署时需要一并构建更新；本批透视表配置无数据库迁移。本地后端已编译并重启加载。

指标条需保留单个 DOM 根节点：占比范围弹窗放在根节点内部，并通过 append-to-body 展示。此前将弹窗与指标条并列导致 Vue 无法透传 Sortable 的 `data-draggable` 属性，指标不能抓取。已修复，新增 `quotaItemDrag.test.cjs` 防止多根节点回归，并在浏览器验证指标向下、向上拖动排序。

指标和维度名称提示为被动提示：浮层 pointer-events 为 none、不可进入，悬停 350ms 显示，移出立即关闭。捕获 pointerdown/mousedown/dragstart 时同时取消待显示提示并立即隐藏已显示提示，拖动中经过其他字段不会重新启用；鼠标释放后重新悬停才恢复。`fieldNameTooltip.test.cjs` 覆盖这套交互和卸载监听清理。

快速计算菜单兼容 `compareCalc=null`、缺省对象和空 type，读取时统一视为“无”；仅在用户选择计算方式时初始化所需配置，查看菜单不改写字段，打开占比范围后取消也不改写原配置。`quotaQuickCalc.test.cjs` 使用真实二级菜单模板进行 Vue 服务端渲染，并验证各计算方式的处理函数、默认配置隔离和既有占比保留。
