# 透视表日期行列与月份显示

日期显示控制查询分组粒度。行维度选择「年」得到 yyyy；列维度可选择新增的「月份（1—12）」得到 MM，不含年份，使多个年份共用月份列。选择月份时默认升序，用户仍可调整排序。

日期格式控制表头表现。月份支持「月份名称（1月）」和「两位数字（01）」，只改变表头，不修改原始月份值或合计。年月等原有粒度保留横线/斜线格式；年份不再展示与之无关的年月日格式，格式菜单显示年份示例。未新增缺失月份补齐能力，仅显示查询结果中存在的月份。

修复覆盖：新拖入的透视表行、列维度与指标均可拥有独立 fieldInstanceId。旧图表的行、列维度若共用 resultKey，会按轴、位置、字段 ID 补齐确定性实例标识；前后端使用相同规则，重复调用与保存还原保持稳定，未冲突的旧维度不改变标识。查询结果及 S2 元数据使用实例结果键，避免同一日期字段的月份结果覆盖年份结果。

使用：将取值时间放在数据行，日期显示选年；将取值时间放在数据列，日期显示选月份，日期格式选月份名称；指标保留业绩。品类等其他行维度可继续添加。

验证：24 项后端测试通过。新增测试使用 2025、2026 两年和 1、2、10、12 月数据，验证日期 SQL 表达式（提供者日期占位符转换为 H2 等价格式函数执行）、结果字典中年份和月份独立、月份顺序、重复月金额汇总、2026 年合计 110 和全表合计 140，以及字段实例 JSON 还原。前端验证旧字段实例稳定、无冲突字段保持原样、月份名称与数字格式、空值处理；九个 Vue 组件编译通过，修改文件 ESLint 无错误。

上线：需要重新编译后端并启动，再刷新前端；本轮未重启运行服务。没有新增数据库列。

## 月份被合并为 MM 的后续修复

实际运行发现内置 Calcite 方言转换器识别 yyyy-MM，但没有转换裸 MM，MySQL 将 DATE_FORMAT 的 MM 当作固定文本。初次测试替换日期占位符直接在 H2 执行，没有覆盖方言转换，遗漏了该问题。

月份 SQL 改为复用已有年月转换，再用 SUBSTRING(...,6,2) 提取月份；该表达式同时用于 SELECT、GROUP BY 和排序。因此不是前端重命名列头，而是数据库按真实月份聚合。

回归测试已改为使用项目实际 SqlParser 与 MysqlSqlDialect 转换整条查询，检查 %Y-%m 和 SUBSTRING 并拒绝裸 MM，执行转换后的 SQL 验证结果。24 项后端测试通过；另外在本地 mysql-de 连接内创建临时表、执行同一条实际生成 SQL，得到 2025/01=10、2025/10=20、2026/01=30、2026/02=5、2026/10=50、2026/12=25。临时表随连接结束消失，没有修改业务数据。需要重新编译后端并启动后，在实际透视表更新数据；运行服务本轮未重启。
