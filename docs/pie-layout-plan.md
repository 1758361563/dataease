# 饼图双布局实施方案

目标：提供可在样式面板切换的大饼图与环图榜单，协调主体面积、标签、配色与信息层级。用户提供的参考文件用于需求参考，实际实现以现有代码与用户授权为准。

## 现状与结构

饼图和环图使用 @antv/g2plot 的 Pie，核心在 src/views/chart/components/js/panel/charts/pie/pie.ts。属性通过 BasicStyleSelector 和 customAttr.basicStyle 保存，编辑、发布、复制与模板继续使用现有 JSON。现有 radius 默认 80%，外置标签使用 spider 布局，普通点击回调进入既有 action 联动。现有前端 TopN 会对渲染数据排序、截断并添加 others，原 drawChart 直接使用查询数据引用，存在展示修改原始结果的问题。分类配色复用 seriesColor，但默认按当前数据顺序映射。

## 产品设计

样式中的「布局样式」最终提供原样式、大饼图、环图榜单。存量缺省仍为原样式，不自动迁移或切换。新布局共享查询结果，不修改 SQL、权限、筛选或指标计算。

大饼图优先圆盘面积，外标签按原始指标值选择主要分类并避让；最大标签数可调，其他真实扇区仍保留且可悬停查看。小卡片采用少量内部百分比标签，避免为长标签挤小圆盘。中性连接线、主题文本和扇区分隔统一处理。分类色优先用户固定色，否则按分类键稳定映射；提供分类色板和主题色板。显示比例继续沿用当前查询结果分母，不能把 Top20 结果称作全量业务占比。

环图榜单显示全部真实分类，左图右榜单，窄卡片改上下布局；列表滚动、分类数量、双向高亮和中心指标必须协调。进度条表示真实占比长度，不用除以第一名数值却标作占比。Top4 集中度不作为所有图表强制中心信息。

「其他」合并为可选功能，默认关闭。启用后仅合并当前查询结果尾部，保存成员原始身份与数值；虚拟项使用独立内部标识与中性色，点击先打开成员明细，不下发虚假分类值。真实名为其他的分类、NULL、空字符串和文本 null 保留区别。明细中的真实成员再复用既有点击动作。

## 三阶段流程

1. 第一阶段：布局配置基础、大饼图首版、标签预算与长名称省略、卡片 resize、稳定配色、渲染数据克隆。只开放已完成的原样式和大饼图，环图榜单不提供无效按钮。验证数据不变、配色稳定、典型宽窄尺寸和普通点击。此阶段不新增长尾聚合，已有 TopN 继续有效。
2. 第二阶段：完成环图榜单与可选其他明细，开放第三个布局选项；验证排序、滚动、双向高亮、明细和点击语义。
3. 第三阶段：在真实仪表板集中验收模式切换保存、主题、筛选、复制、截图和数据导出。截图显示可见榜单并标明分类总数，全量明细继续走数据导出。只修复验收中实际发现的问题。

## 配置与代码方案

basicStyle 增加 pieLayout（缺省 legacy，large；第二阶段增加 ranking）、pieLabelLimit（缺省 8）、piePalette（categorical/theme）。大饼图模型单独放在 piePresentation.ts，负责尺寸策略、重点标签和颜色解析；Pie 类应用模型，不把布局规则散落在通用绘图层。BasicStyleSelector 提供布局缩略图按钮及必要的少量配置。ChartComponentG2Plot 的尺寸监听仅对新饼图布局重绘，保持其它图表原行为。阶段二沿用这份展示模型扩展，不新增图表类型。

验证不以截图示例四舍五入后的百分比为计算输入。阶段一使用原始值、空值、长名称、8/20/50 分类与宽窄尺寸，测试总值与数据对象不被改写。实际浏览器检查标签与扇区，不能仅以数学测试宣称视觉无重叠。

## 第一阶段完成记录

已完成样式面板双缩略图入口：原始布局、大饼图。大饼图开放最大标签数与色板策略，自动分配圆盘与标签空间；窄卡片改为少量内部百分比。圆盘模式自动管理半径，因此隐藏与它冲突的手动半径、内半径控制。渲染前克隆查询结果，防止现有 TopN 修改原始数据。所有真实分类仍保留，未实现新的其他合并，也未开放环图榜单按钮。

G2 内置 spider 布局会因被隐藏标签产生的 null 项报错；新模式使用专用布局注册，先过滤空标签项，再依次执行 spider、避让与边界限制，保留原始扇区几何及点击事件。布局注册通过 G2Plot 导出的 G2 共用同一绘图引擎。

已验证：`node tests/piePresentation.test.cjs`（标签数量、数据不变、宽窄尺寸、单/双分类、非正数、NULL 与文本 null、颜色不受排序/筛选改变、用户固定色优先、长名称、省略标签的顺序布局，以及两个 Vue 组件编译）；修改的四个前端文件 ESLint 通过。实际浏览器使用 DataEase 的 Pie 渲染器绘制 900×450 与 360×260 卡片，包含 18 分类与 NULL，确认绘图正常、控制台无错误、原始数据与扇区数保留，点击真实扇区进入既有 action 回调。

使用入口：编辑饼图 → 样式 → 图表属性 → 布局样式 → 大饼图。这一阶段只有前端变更；开发服务刷新即可加载，正式静态部署则需要重新构建前端。真实仪表板的保存、复制、导出及完整联动验收按第三阶段集中执行。

## 第二阶段完成记录

已开放第三个缩略图「环图榜单」，饼图和原环图均可切换。宽卡片左图右榜，宽度小于 600px 时上下排列，榜单独立滚动。榜单显示项按数值降序；进度条按当前结果总计计算，默认中心展示总计与真实分类数量，悬停/键盘聚焦时改为分类、占比和数值。扇区与榜单双向高亮，其他扇区淡化；被悬停的榜单项超出可见区域时自动滚入视野。

复用已有 calcTopN/topN/topNLabel 保存可选合并规则，避免新增同义配置。新布局将开关文案改为「将尾部分类合并为其他（可查看明细）」。未勾选时显示全部分类；勾选时保留金额最大的 N 类，把余下成员汇总为其他。虚拟项使用独立 pieKey，真实「其他」、NULL、文本 null、空字符串不会混在一起。其他聚合保留成员原始维度/指标身份及额外 tooltip 指标合计；其本身没有可用于联动的维度值。点击其他仅展开明细，点击成员才转发真实分类事件。大饼图同样支持这一明细面板。

展示模型只操作克隆的查询结果。新布局的负值/无效值不参与占比，榜单会提示排除数量；比例分母为当前查询返回结果中的有效非负值，不代表未查询出来的业务全量。配色沿用第一阶段，未调整色板，仅修复内部身份键与原分类之间的取色映射。Vue 面板与原 G2Plot 实例一起销毁，尺寸变化时重绘以切换横向/纵向布局。

验证通过：纯模型与实际取色方法回归测试、三个 Vue 组件编译、修改文件 ESLint、新增面板 Stylelint；实际 DataEase Pie 渲染器在 900×440 / 360×500 卡片上显示 25 分类。浏览器确认榜单滚动、焦点到扇区高亮、扇区到榜单高亮、总计/占比、真实「其他」和 NULL 的点击身份、虚拟其他不触发联动、成员真实点击，以及环图榜单/大饼图反复切换清理。控制台无错误。截图、保存发布、复制及业务数据联动仍按第三阶段集中验收。

## 布局与色板调整

按用户后续要求移除原样式入口，现在仅显示大饼图、环图榜单；新图默认大饼图，旧配置缺省或 legacy 在渲染及编辑时兼容为大饼图。公共 COLOR_CASES 替换为用户提供的现代商务、观远柔和、莫兰迪三套八色方案（色值按截图文字录入），默认/浅色/深色图表的初始分类颜色统一为现代商务。地图继续通过现有逻辑生成九阶渐变。

删除饼图独立配色策略入口，绘图、榜单统一使用公共配色方案及已指定的分类颜色。已有图表保存的 colors/seriesColor 不批量改写，重新选择方案即可应用新色板。重置颜色时复制预设数组，防止单个图表的自定义颜色修改公共预设。已验证三套八色十六进制值、旧布局兼容、旧 piePalette 不覆盖公共方案、四个 Vue 组件编译及修改文件 ESLint。

后续修复：默认取色从哈希映射改为按当前展示顺序依次使用色板，前八个普通分类覆盖完整八色，超过八类循环；显式分类固定色仍优先，虚拟其他保持灰色且不占用普通分类颜色位置。筛选改变分类集合时默认色序可能变化，如需固定分类颜色使用自定义分类色。饼图与榜单共用这一映射。

提示标题通过内部 pieKey 查回真实分类名称，普通与显式 tooltip 均应用。正文最低 14px、标题最低 16px，保留更大的用户字体设置；容器增加留白，宽度 240–360px，长标题允许换行。色板名称简化为均衡分类色、柔和多色、低饱和；选择弹层扩大至 320px 并释放原先只有 40px 的名称区域。回归测试验证三套色板八色顺序、循环、真实提示标题与字体配置。此次浏览器工具无可用连接，未进行本轮页面实测。

按后续截图收紧提示：保持可读字号，取消固定最小宽度，改为按内容决定宽度（最大 320px），内边距 8×10px、标题中等字重、缩小行距。圆点、名称、数值紧邻排列，不再将数值推到容器最右侧。单位与精度继续使用指标自身配置。大饼图悬停事件移出 Vue 面板存在条件，普通大饼图也能高亮当前扇区、淡化其他扇区，离开时还原。回归测试直接执行真实 highlight 函数并检查事件注册位置，验证高亮及还原；同时验证提示样式配置，ESLint 通过。
