# 数据集预览性能改造与本地验收

## 当前改动

- 字段单独通过 previewFields 加载，仅读取数据集定义并过滤列权限，不执行明细 SQL。已有数据集仍检查 READ 权限，已有数据集草稿仍检查 MANAGE 权限。
- 交互预览取消默认全输出列排序，保留明确配置的排序；未配置时页面标记“快速预览”，不承诺页间固定顺序。候选值按单个候选字段排序。导出的原有排序回退保持不变。
- 明细及候选值使用 SQL 分页，每页 50/100/200 行，多取一行判断 hasMore。JDBC 同时限制返回行数。过滤、权限和选列仍在服务端处理。
- 默认不计算总数。统计总数/统计匹配数量由用户触发，失败不阻塞明细。当前页面同筛选翻页复用已统计总数，悬停可查看统计时间；没有跨用户数据缓存。
- 普通预览使用前后页，不依赖精确总数。交互深分页最多覆盖前一万行，之后通过筛选定位或后台导出；这不是给整个数据集加一万行过滤，也不限制图表数据。
- 预览专用执行上下文：每后端实例 4 个明细/候选值名额、1 个计数名额。满载立即提示繁忙，不创建无限队列、不自动重试。
- 明细/候选值 JDBC 最长 15 秒、计数最长 5 秒；保留数据源本来更短的超时。前端请求 20 秒兜底。权限解析、获取连接耗时也计入后续 SQL 剩余预算，但 JDBC 连接池等待仍由原连接池设置约束。
- 每次查询带独立 UUID。切换条件、数据集、离开页面或点击取消时，AbortController 中止请求并调用用户隔离的 previewCancel，尝试 Statement.cancel()；提前到达的取消短暂保留，防止随后查询仍启动。关闭 JDBC 绑定后不再取消已经归还的连接。
- 读取结果时检查取消/截止时间及一百万字符的页面数据预算，超过预算整次失败并提示减少列/行数，不静默截断结果冒充完整页。它不是驱动层单元格下载大小限制。
- 超过一秒的请求记录数据集 ID、查询 ID、类型和耗时，便于匹配明细与计数；日志不新增筛选值或业务数据。
- 本次上下文只包裹 previewQuery/previewValues/previewCount；仪表板、ETL 和导出沿用各自的运行策略。慢预览失败不再阻止提交后台导出，导出仍受原导出权限及执行机制约束。

## 本地验收后再统一部署

使用只读访问完成以下测试，不灌数、不改正式表、不先创建索引：

1. 以财务宽表数据集打开无筛选预览：记录字段到达时间、首屏耗时、实际生成 SQL，确认无默认全列 ORDER BY，默认无 COUNT 请求，页面只收到最多 100 行。
2. 分别使用一天、一个月、两年的日期区间，验证日期和行权限在 SQL 内生效；连续翻页不重复统计总数。缩小显示列后核对投影。
3. 手动统计总数，确认计数超时仍可浏览；打开筛选器不计数，搜索候选值可取消。
4. 查询运行中换筛选/离开页面/取消，检查旧结果不覆盖新结果，并在数据库侧确认旧语句停止。验证当前 MySQL JDBC 驱动实际支持查询超时和取消，检查连接池没有被持续占满。
5. 多标签页触发慢查询，检查并发名额和繁忙提示；后台任务/图表仍按各自机制运行。注意它们仍共享 RDS，预览限流不等于数据库整体资源隔离。
6. 验证列权限、隐藏列、受限用户筛选与导出；抽查导出的排序与行数不因本次修改变化。
7. 提供正式表的 SHOW CREATE TABLE、SHOW INDEX，以及首屏 SQL、典型日期筛选 SQL 的普通 EXPLAIN。可以隐去主机和连接信息。不要直接对重查询执行 EXPLAIN ANALYZE。

## 需要上述证据决定的部分

- 数据集字段模型没有可靠的“输出行唯一键”契约。游标分页不能猜某个日期/编码唯一；关联及聚合后的唯一性也不能照搬底表主键。本次保留有界 offset 分页，没有启用通用游标分页。
- 根据物理表主键、数据集 SQL 和执行计划，判断能否增加可验证的唯一键分页，以及实际需要的日期/渠道联合索引。没有自动改业务库结构。
- 任意复杂 SQL 的 LIMIT 不保证内部关联、聚合、排序都提前结束。若仍超时，应根据执行计划修改查询/索引，而非扩大前端拉取量。
- Cancel 注册表按进程保存。多后端实例部署需请求亲和性或分布式取消路由；取消请求落到其他实例时由原实例 JDBC 超时兜底。第三方数据源 Provider 或跨源 Calcite 的取消传播效果需要对应驱动验收。
- 缓存只限页面内已请求的计数，带统计时间；未实现共享明细缓存，也未建立跨页一致性快照。预览期间底表更新可能改变后续页。

前后端需要一起更新。这份清单用于部署前的本地验证；代码检查通过不代表真实宽表已经达到指定首屏耗时。

## 字段显示名称补充验收

- 新读取的字段默认使用物理字段名或 SQL 输出别名；数据库备注只存入 description。已有字段名称不自动覆盖。
- 数据集编辑 → 字段管理 → 恢复原字段名：默认不勾选，可选择“名称与备注相同”的字段或手动勾选，窗口显示修改前后名称。应用只修改草稿中的 name，保存数据集后生效；ID、originName、类型、计算表达式和备注不变。
- 计算/分组字段不参与恢复；所选字段已移除、恢复后名称冲突或超过显示名称长度限制时阻止应用。
- 原重命名入口改称“修改显示名称”；字段列表、筛选器、表头和选列窗口的悬停提示区分原字段名与备注。
- 本地检查：新建带 COMMENT 的测试数据集、手动别名、批量恢复后的取消/保存、重名冲突、原有图表按字段 ID 的绑定。代码回归增加了默认名称及四项字段命名测试。
