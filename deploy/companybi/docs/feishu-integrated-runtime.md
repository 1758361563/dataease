# 飞书随 BI 交付：运行、迁移与扩展

此文描述源码改造后的部署方式，不代表塔内服务器已经升级或真实推送已经验收。

## 部署与配置

部署对象仍为 BI 应用及其元数据库。BI 镜像内包含 Java 后端、私有 Node 执行器及 Chromium；后端通过进程标准输入/输出调用执行器，不使用独立 HTTP 服务或 8091 端口。配置连接后，后端随启动拉起执行器、检测异常退出并重启，关闭时回收子进程和浏览器。镜像体积及截图期间的内存占用会增加，应在塔内部署前以实际镜像测量。

“权限管理”只保留用户、用户组、资源授权和审计；“集成中心”包含飞书订阅和应用连接。旧订阅 URL 与卡片入口保持跳转兼容。移动导航不会增加账号权限：仍由后端校验飞书管理能力，修改凭据及验证连接仅限初始管理员。

应用连接直接填写 App ID、App Secret、截图账号和密码。留空的密钥保持原值；更换应用须重新填写密钥并先停用已有订阅，原应用收件人不会自动改归属。截图账号应能查看订阅涉及的仪表板。应用连接保留正常的启停设置；各订阅独立配置启停状态、发送计划和自动触发。不提供模拟发送、测试通道或额外的全局发送/调度开关。连接启用后，“立即发送”和到期计划都执行完整推送流程。关闭连接阻止后续工作，不撤回已发送消息，也不立即杀死正在执行的发送。

“验证连接”真正调用飞书应用认证和只读通讯录接口，分别显示权限和浏览器安装状态，不发送测试消息。它不代表截图账号登录、具体仪表板权限、真实上传发送及全链路已验收。

## 凭据及持久化

新增 `company_integration_connection`，以 provider + connection_key 定位连接。公开设置与加密凭据分开，AES-GCM 附加认证数据绑定 provider 和连接标识，页面只返回密钥存在状态。现有订阅、收件人、执行记录及 ID 保留，飞书旧应用表只作兼容映射，不存明文密钥。

加密密钥由稳定的 `COMPANY_BI_TOKEN_SECRET` 经带用途区分的 SHA-256 派生；务必将原部署密钥与元数据库一起备份。直接更换部署密钥会使既有集成凭据无法解密，须先设计重加密迁移，不能只编辑环境变量。执行器经私有进程环境读取数据库连接和解密密钥，不从开发目录 `.env` 加载，不依赖 Docker CLI，也不回退到内置数据库凭据。

截图与执行日志位于持久化数据目录的 `integration/`。执行器的请求和响应不写进后端日志；错误信息脱敏，页面不回显密钥。任务级重试、已成功收件人跳过及执行历史沿用已有逻辑；历史未投递记录不会升级为新的发送任务。执行器独占租约和每次调度锁均持有专用 MySQL 连接。

## 从原独立服务迁移

1. 备份元数据库、部署密钥与原独立服务私有配置；记录旧执行器运行位置。
2. 停止原独立执行器后再切换，避免新旧调度并行；不要同时启用两者。
3. 部署包含内部执行器的新 BI 镜像，在应用连接里重新录入原应用凭据。原环境变量形式的密钥不会被自动读取或上传。
4. 开启连接后验证认证及通讯录，验证添加员工；用测试环境的账号和仪表板验收完整的截图、上传、发送流程，确认长 ID、配置和历史均保留。
5. 在受控收件人上验收发送、失败与重启恢复，再按业务需要启用订阅及发送计划。仅本次源码改造不代表已向真实员工发送消息。

若订阅关联 ETL，仍需取得覆盖业务日的正式成功记录；没有记录不能冒充校验成功。内置模式不会假定存在某个公司业务库，默认只查元数据库中的 `etl_run_log`。跨库/跨实例的 ETL 日志来源需要后续按数据源连接接入，在接通前相关计划会阻止发送旧图。

旧独立服务中的特定门店表格同步、自动种子配置不会随 BI 升级激活。既有 source 表数据保留；如果有实际使用中的旧表格任务，应先迁移任务来源和目标连接再停其原调度，不把本次升级视为表格任务已迁移。

回滚旧镜像不会删除新增连接表，但旧独立服务不识别加密连接。新配置已写入兼容应用表后，旧执行器也不能直接依赖 `BI_MANAGED_FEISHU_SECRET` 工作；须按备份恢复原密钥引用及原环境配置，并保证只有一个执行器运行。不要自动恢复整库或自动开启真实发送。

## 后续数据能力的边界

应用连接是可复用的认证资源，不是订阅的一部分。新增 provider 或同一 provider 的多连接时，沿用 provider + connection_key，不把所有任务绑到单个全局应用、订阅 ID 或某一张飞书表。

未来“飞书表格 → 数据库镜像”使用独立的导入任务：选择应用连接、解析输入 URL 的 spreadsheet/sheet 标识、选择有写入授权的目标数据源及库表、保存字段映射和同步策略。目标连接复用 BI 数据源管理；不把元数据库当作默认业务目标，不硬编码门店、数据库或表名，不自动创建未经选择的业务镜像表。

未来“BI 卡片 → 飞书表格”使用独立的导出任务：绑定卡片及其查询参数，选择目标表格和区域/工作表、追加或覆盖策略。它读取卡片查询数据，而非复用图片截图；必须以任务授权身份执行查询，保留数据集和仪表板权限检查。

两种方向共享应用认证、调度与运行观察能力，但分别保存任务配置、字段映射、进度、幂等标识及失败状态，不给订阅表增加相互耦合的表格参数。当前没有创建这两个未来功能的假页面、自动任务或业务表；`company_feishu_source` 的历史结构不作为未来双向同步的固定模型。

## 开发验证方式

产品与测试环境使用同一套正式业务流程，不通过页面开关、测试通道或模拟模式跳过截图、上传、发送。自动化测试通过独立数据库与仅测试进程加载的外部接口替身隔离，替身模块不进入运行镜像。测试用应用、账号、收件人和数据属于环境配置，不构成产品功能。旧库里的未投递历史仅如实显示，不能冒充已发送，也不会被补发。
