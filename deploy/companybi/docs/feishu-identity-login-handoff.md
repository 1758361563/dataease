# 飞书账号绑定、登录与工作台接入

## 本次交付

- 用户管理新建、编辑：按飞书姓名搜索，显示部门、ID 尾号与已占用的 BI 用户；可绑定、更换、解除绑定。
- 用户创建和绑定在同一事务内保存。绑定失败时回滚用户创建；用户修改记录包含绑定前后状态。
- 复用 `company_feishu_identity_map` 与个人收件人，不建立第二套账号关系。
- 订阅选择器新增“BI 用户”分组，直接选择已绑定的有效用户，与普通飞书联系人去重。
- 登录页增加飞书扫码；飞书客户端使用 `requestAccess`，不支持时回退 `requestAuthCode`。
- 集成中心 → 应用连接增加“登录与工作台”配置，展示可复制的回调地址和主页地址。
- 登录成功后进入原访问页面；移动端飞书登录入口和回调先完成认证，再进入既有移动端页面。

## 身份与生命周期

新绑定标记为 `USER_ADMIN_VERIFIED`，成员 ID 由现有通讯录服务重新核实。订阅接口不能创建登录绑定，也不能修改已绑定收件人的身份。

旧 `MANUAL` / 观远导入映射不能直接用于登录。管理员在用户编辑页面选择并保存同一飞书成员即可核实升级，保留原收件人和订阅。

更换或解除绑定前，若原收件人仍被未删除的订阅引用，页面提示订阅名称。先移除该收件人再操作；不会把原订阅自动转给新成员。已删除订阅不阻止解绑，收件人和发送历史保留。

飞书登录令牌含绑定 ID 和应用 ID，后端每次请求检查绑定仍有效以及 BI 用户状态。解绑、更换绑定、停用用户、关闭飞书登录后，相关会话无法继续使用。令牌最长 12 小时，沿用公司版登录的前端免刷新方式，后端校验到期时间。

登录限定配置的 `tenant_key` 和应用。用户信息缺少 `user_id` 或企业标识时拒绝登录；不按姓名、邮箱猜测绑定，也不自动建 BI 用户。

订阅仍使用现有截图和发送机制；绑定不会改变截图账号、仪表板授权或自动创建订阅。消息实际发送状态与身份验证状态分开记录。

## 部署与飞书后台配置

需要重建前端、后端和 SDK common；包含登录白名单修改。后端启动自动创建 `company_feishu_login_attempt`，只在 BI 元数据库保存临时授权状态，不修改业务宽表。

1. 在应用连接中保存并启用现有飞书应用，确认通讯录查询可用。
2. 在“登录与工作台”填写 BI HTTPS 根地址和企业 `tenant_key`，保存配置。本地调试可以使用 `http://localhost:端口`。根地址须与用户实际打开网页的来源一致；Vite 开发时对应其代理入口。
3. 飞书开发者后台为同一企业自建应用启用网页应用能力，保留机器人能力。
4. 将页面给出的授权回调地址登记到安全设置，例如 `https://bi.example.com/de2api/login/feishu/callback`。
5. 桌面和移动端主页配置为页面给出的 `https://bi.example.com/#/login?feishu=1`，按飞书要求配置 JSAPI 安全域名。
6. 确认通讯录范围、获取用户 User ID 权限、应用可用范围覆盖测试员工。发布版本并完成企业管理员审核。
7. 在 BI 用户管理中绑定测试员工，再验收扫码登录、工作台打开和订阅发送。

飞书客户端内的设备必须能够访问 BI 地址；内网地址仍需相应网络或 VPN。工作台应用入口与飞书左侧固定入口分别由飞书管理，BI 不控制用户的固定导航。

应用变更后需重新保存登录设置。其他应用的 `open_id` 不迁移到本应用。本实现使用应用内已验证的 `user_id`，登录时同时核对企业和应用，不要求填写 open_id。

## 授权请求保护

- 随机一次性 state；浏览器 sessionStorage 保存独立随机校验值，数据库只存二者的 SHA-256。
- 授权请求 5 分钟失效，数据库条件更新保证多个实例只能消费一次。远程兑换失败也不会重放原请求。
- 回调地址来自管理员配置；回跳只接受站内路径。BI 令牌通过响应体返回，不放入 URL。
- Secret 复用现有加密应用连接，OAuth 临时令牌只在后端处理，不保存或输出原始认证响应。
- 接口有实例内请求频率限制。部署网关仍应按实际代理拓扑配置限流，服务端不会信任任意客户端提供的转发地址。

## 部署后验收

- 创建并绑定员工；同名人员可区分；已被其他 BI 用户绑定的成员不可选；失败后无半成品用户。
- 已绑定用户在订阅收件人中出现一次，原有个人/群聊发送正常。
- 浏览器扫码、飞书桌面工作台、飞书手机工作台分别以绑定用户进入；账号角色和原有 BI 权限生效。
- 未绑定、其他企业、停用用户有明确提示；过期二维码可刷新。
- 解除或更换绑定后旧飞书会话失效；仍被订阅使用时提示具体订阅。
- 多实例使用同一数据库和 BI 签名密钥，验证同一授权请求只能成功一次。
