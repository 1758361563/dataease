# 数据更新二期：实现与验收交接

本轮已修改代码，仅执行代码编译、静态检查、单元测试。未连接真实数据库执行建表、抽取或聚合，也未启动部署服务。

## 用户入口

数据准备 → 数据源 →「数据更新」页签。支持 MySQL、PostgreSQL、SQL Server 数据源；已有表旁的「数据更新」按钮继续保留。

「新建更新任务」支持填写已有表名，先读取真实结构再进入刷新配置；MySQL 还提供「手写 SQL 建表」。建表 SQL 与查询/聚合 SQL 各自执行，定时刷新不会重复建表。

手写建表流程：输入目标表名和 SQL → 检查建表 SQL → 执行建表 → 读取真实结构 → 使用此表配置刷新。建表记录独立显示状态、已完成步骤和失败信息。

## 已实现的建表能力

- 使用 JSqlParser 解析语句结构。第一条为目标实表 CREATE TABLE，后续可为该表 CREATE INDEX。校验数据库和目标表名。
- 支持字段、主键、索引、InnoDB、字符集、排序规则和备注。复杂生成表达式、外部表引用、外键、临时表、CTAS/LIKE、修改/删除表及客户端命令不属于受管建表入口的语法范围。
- 已有表会提示改用已有表；IF NOT EXISTS 不作为新建成功的依据。
- 独立操作 ID 与 SQL 哈希保证重复请求读取同一次操作结果。已在执行的请求不会因为重复提交再次执行。
- 建表及索引每步记录进度。DDL 部分成功或结果未知时保留目标占用，状态为 `NEEDS_REVIEW`，不自动重放或删表补偿。
- 用户确认旧执行结束并核查表与索引后，可「核查并解除占用」；服务重新读取实际结构，并在持有执行锁时复核操作状态。
- 建表审计记录与初始化记录先持久化，再执行目标 DDL。审计中记录操作 ID 和动作；SQL 保存在受管理员权限保护的操作记录中。

## 字段检查与运行校验

查询抽取配置增加「检查字段」「预览最多 20 行」。检查会访问数据库，源查询设置 15 秒执行超时；数据库连接超时仍由数据源连接配置与驱动控制。

检查重复列名、目标缺列、必填字段缺失、字符串容量、decimal 精度、明显不兼容的数值/日期转换、主键和窗口字段。可空性、其他类型转换、自动生成字段显示需要确认的提示。查询未改变且检查存在错误时，页面阻止保存；存在提示时要求用户确认。

检查成功后，将目标结构指纹写入任务定义。正式执行前重新读取并比较指纹。兼容旧配置：尚未进行字段检查的既有任务仍可运行；建议在接管正式调度前检查并保存一次。

正式抽取还会依据实际结果元数据检查字段类型/容量；MySQL 抽取目标连接启用严格写入模式，避免数据库静默截断数据。保留暂存、事务写入、主键与窗口校验，并新增最小抽取行数。结构及类型检查不替代实际数据约束和业务对账。

预览最多 20 行、256 个字段，每个普通文本单元最多 512 字符，完整检查响应限制 128 KB。大字段与复杂类型省略；预览行不写入审计或运行历史。

## 任务组与批次

任务组在目标数据源页签创建，选择完整的依赖链，配置组名、时区、Cron 和自动调度开关。源数据库可以不同，组内任务目标归属于同一数据源。一个任务至多属于一个组。

- 加入组后，独立定时/依赖触发与单任务手动运行被阻止，统一从组入口执行。
- 手动整组运行可指定业务日期。每批固定组定义及所有任务的配置版本和执行顺序，共享上游每批只执行一次。
- 当前实现按拓扑顺序串行执行节点，减少并发状态与失败处理的复杂度。每个实例同时执行一个任务组批次；独立任务保留原执行并发设置。
- 为所有受管目标一次性持久化占用，再由一个元数据库连接申请全部目标会话锁。申请失败不会持有部分锁等待。
- 下游仅消费本批成功的上游。节点失败后阻断后续节点，已完成输出保留；各表分别提交，不承诺全部输出同时发布。
- 取消排队批次立即释放其占用；取消运行批次等待执行退出后释放。进程中断或失锁保留占用并进入待核查状态，确认旧执行结束后才能解除。
- 定时触发遇到资源占用等校验阻断会记录 `SKIPPED`，不会自动重试。
- 批次记录支持展开节点状态、处理行数和结果。任务列表显示最近结果与最近成功时间（UTC）。

组运行期间可以保存成员任务的下一配置版本；当前批次继续使用已保存快照。组成员和组定义调整须等当前批次结束或核查完成。解散组会保留任务并恢复其原独立调度设置，操作前页面会提示核对开关。

应用层资源占用管理本功能提交的写入。完整 SQL 脚本应只写声明的目标表及自身中间表；旧 ETL、外部脚本、其他数据源别名和数据库直写需由部署接管流程处理。两个源查询各有自己的读取时刻，不提供跨数据库分布式快照。

## 代码组成

- `UpdateDdl` / `UpdateDdlService`：DDL 语法约束、操作去重、部分成功、回读与核查。
- `UpdateInspection`：结构元数据、指纹、字段兼容性、受限预览。
- `UpdateGroups` / `UpdateGroupRuntime`：组定义、成员、批次快照、节点执行、资源占用及组调度。
- `UpdateSetupController` / `UpdateGroupController`：沿用 `ETL_ACCESS` 管理员授权与审计。
- `DataUpdateWorkspace.vue`：新页签、建表、新建任务、任务组与批次记录。
- `DataUpdateDrawer.vue`：原刷新配置扩展字段检查、预览、指纹和最小行数。

新增六张元数据表：`company_data_update_ddl`、`company_data_update_claim`、`company_data_update_group`、`company_data_update_member`、`company_data_update_group_run`、`company_data_update_group_node`。现有 schema initializer 在启动时创建；原任务定义 JSON 向后兼容新增字段。
