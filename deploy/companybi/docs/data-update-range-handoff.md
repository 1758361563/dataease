# 首次同步与历史补跑

2026-11-03，代码交付。

## 操作

- 全量替换默认隐藏最近天数；SQL 显式使用日期参数时仍显示参数设置。
- 窗口覆盖配置日期字段与最近 N 天。普通查询由系统在查询结果外添加日期条件；复杂查询可自行使用 `{{window_start}}`、`{{window_end}}`。
- 主键更新：日期字段留空读取全部查询结果；填写字段后读取最近 N 天。仍保留按主键更新已有记录、插入新记录的语义，不自动删除源端消失的记录。不支持自动水位推进。
- 日常“立即更新”使用已保存配置，移除业务日期输入。
- 尚无成功记录时显示“首次同步”，支持指定日期和全部查询结果。全部初始化会替换目标内容；含日期参数的查询需选择明确范围。
- 成功同步后显示“补跑历史”。直接选择包含起止两天的日期区间，选择区间覆盖或主键合并。范围补跑不允许全表替换。
- 脚本补跑必须同时使用起止参数，实际写入逻辑由脚本决定。

## 执行约定

一次执行的范围、策略及 SQL 固化在运行配置快照中，不改写日常配置。服务端将包含终日的范围转换为次日零点之前，支持 1970 年起、最长 3660 天；记录直接返回并展示开始及结束日期。无需数据库结构迁移。

范围执行复用现有版本检查、目标锁、队列、取消、超时及事务机制。首次全部初始化的资格在入队事务内再次核查。首次和补跑结果不充当日常依赖成功凭据，不推进日常新鲜度，也不消耗日常依赖批次。

当前范围入口面向独立任务；有上游依赖或已加入任务组时禁用。任务组原有按业务日期补跑机制仍保留，整组任意日期范围编排另行扩展。飞书继续全量快照。

普通查询的日期字段必须在查询结果中存在，窗口覆盖时目标表须有同名日期字段。涉及聚合、CTE 或数据库特有语法的查询，优先在正确的计算层级显式写入起止参数，避免外层筛选改变计算口径。

## 验收

代码检查覆盖闰年、终日包含、反向区间、范围全表替换拒绝、主键要求、配置快照隔离及全量不添加日期筛选。环境验收：首次读取一年后日常覆盖最近七天；补跑单月保留其他月份；按主键回写旧订单；断连回滚；确认日常计划和下游未被补跑推进。
