## 2026-10-21：个人修改密码接口缺失，页面误报成功

- 状态：已修复并在测试 ECS 发布；真实 API 验收通过，使用临时账号验证，真实 admin 密码未修改。
- 发现版本：`f44a180699ff72862216cf7ea7d81fc71d36145f`，镜像 `companybi:2.10.25-20261021-f44a1806`。
- 影响：Company BI 认证模式下，个人设置中的“修改密码”不能正常修改密码；不能依据页面成功提示判断密码已更换。

### 复现与证据

1. 登录后打开修改密码，输入旧密码、新密码与确认密码，保存。
2. 页面同时提示 HTTP 404 和“修改成功，请重新登录”。
3. 用户确认：重新登录时新密码无效，旧密码仍然有效。
4. 已只读核对部署访问日志：2026-10-21 18:08:43、18:09:27（北京时间），`POST /de2api/user/modifyPwd` 均返回 404。未读取或记录请求体及实际密码。

### 已定位原因

- 前端 `core/core-frontend/src/views/system/modify-pwd/UpdatePwd.vue` 的 `save()` 调用 `/user/modifyPwd`，在 Promise 成功回调中显示成功并触发登出。
- Company BI 的 `core/core-backend/src/main/java/io/dataease/company/bi/auth/CompanyUserServer.java` 提供用户信息、语言切换等接口，但没有实现 `/modifyPwd`。SDK 的 `UserApi` 声明不等于该 Company BI 控制器实际提供了接口。
- `core/core-frontend/src/config/axios/service.ts` 的 HTTP 错误拦截器对一般 404 显示错误后返回 `Promise.resolve()`，使调用方的成功回调继续执行。该行为存在影响其他调用方的可能，修复时需检查兼容性，不能只隐藏报错。

### 后续最小修复与验收

- 实现当前已登录用户的密码修改，使用 Company BI 现有用户表及密码哈希机制；校验旧密码、新密码规则及加密参数，不允许通过请求中的用户 ID 修改他人密码。
- 密码持久化成功后才能提示成功；旧密码错误、HTTP 404/500、网络失败等情况均不得误报成功。
- 使用隔离测试账号验证：修改成功后新密码可登录、旧密码不可登录；错误旧密码不改变存储；未登录及越权请求被拒绝。覆盖前端失败分支及后端接口回归。
- 验证长密码边界与现有登录一致；若修改全局 Axios 错误处理，检查现有依赖其行为的调用方，避免扩大改动范围。
- 不以真实管理员账号做自动改密测试。部署修复版后，由用户在页面自行修改管理员密码。

### 运维说明

`COMPANY_BI_BOOTSTRAP_PASSWORD` 仅用于首次初始化，不会随页面改密同步更新，也不能靠修改 `.env` 更新已有账号密码。本次未修改管理员密码、初始化凭证、元数据库或部署配置。

### 本轮修复

- 实现 `/user/modifyPwd`，校验当前登录身份、旧密码、新密码复杂度，使用带旧哈希条件的原子更新防止并发覆盖，不接受修改他人 uid。
- 前端只在响应明确为 `code=0` 时提示成功并登出，防止共享 Axios 拦截器将 404 转为 undefined 后误报成功；未全局改变历史拦截器行为。
- 回归发现 BCrypt 超过72字节会报错，超过该长度的新密码采用带 `{pbkdf2-sha256}` 标识的 PBKDF2 哈希，保留已有 BCrypt 哈希兼容，避免截断密码。新旧密码、128位边界、越权、匿名、错误密文和并发冲突均有回归覆盖。
- 回滚注意：旧版本不识别新引入的长密码哈希。若升级后设置了超过72字节的密码，回滚旧镜像时应按回滚手册评估恢复升级前元数据库备份；恢复备份会同时回退升级后的其他元数据库变更，不能只切旧镜像后假定该密码仍可用。短密码与原有账号哈希格式保持不变。
