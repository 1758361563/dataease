# 数据更新：调度计划

入口：数据源 → 数据更新 → 调度计划。采用方案 01 的紧凑时间列表。

功能：选择北京日期，按时间升序查看已启用的定时计划；搜索目标表、任务组、数据源，按来源与数据源范围筛选；每页 50 行；点击目标表查看详情并进入现有配置和运行记录。

时间由后端 Quartz CronExpression 按配置时区计算，再归入北京时间的自然日。每天、每周、每月、多时点均使用相同计算逻辑；每个调度每日最多展示 1000 次，截断时页面提示。该接口只读取配置并计算，不修改调度、不提交运行。

组内任务使用组的计划，不重复列出独立 Cron。依赖行列出所属计划时点，并标记“上游完成后”；实际执行仍由运行器判断完整上游成功条件。最近结果和最近成功来自任务状态，不表示所选日期的历史结果。脚本任务的策略显示“脚本控制”。

已启用但不属于当前实例、或运维停用的计划显示“当前实例未启用”。计划配置投影不等同于 Quartz 已注册或实际启动记录。

代码验证：`node tests/updateSchedule.test.cjs`（frontend 目录）、`deploy/companybi/scripts/test-data-update-code.ps1`，以及修改组件 ESLint。前后端需要一起发布。
